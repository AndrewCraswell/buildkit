# Theming

[Documentation](README.md)

Import one package stylesheet before your application's theme CSS. Defaults remain for tokens you do not override. Use
unlayered `:root` and `:root.dark` rules after the package import for reliable overrides.

| Group             | Variables                                                                                                                                                                         |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Page              | `--background`, `--foreground`                                                                                                                                                    |
| Surfaces          | `--card`, `--card-foreground`, `--popover`, `--popover-foreground`                                                                                                                |
| Actions           | `--primary`, `--primary-foreground`, `--secondary`, `--secondary-foreground`                                                                                                      |
| Supporting colors | `--muted`, `--muted-foreground`, `--accent`, `--accent-foreground`, `--destructive`                                                                                               |
| Controls          | `--border`, `--input`, `--ring`                                                                                                                                                   |
| Shape             | `--radius` (a CSS length)                                                                                                                                                         |
| Charts            | `--chart-1` through `--chart-5`                                                                                                                                                   |
| Sidebar           | `--sidebar`, `--sidebar-foreground`, `--sidebar-primary`, `--sidebar-primary-foreground`, `--sidebar-accent`, `--sidebar-accent-foreground`, `--sidebar-border`, `--sidebar-ring` |

Colors accept complete CSS color values such as hex, `rgb()`, or `oklch()`, not bare HSL channel lists. Set foreground
tokens alongside their background tokens and check contrast for your chosen colors. Related tokens are independent:
changing `--primary` does not automatically change `--sidebar-primary` or chart colors.

## Dark mode and fonts

Toggle `document.documentElement.classList.toggle("dark", isDark)` in client code. If the app persists the preference,
apply it before first paint to avoid a theme flash. In server-rendered apps, prefer a server-readable preference so
server and client markup agree. Theme selection is the application's responsibility; no theme provider is required for
the core component styles. Sonner's theme prop or its `next-themes` integration should match the selected mode.

Set fonts on `body` and load font files in your app. Override `--font-sans` and `--font-mono` for utility-based text.
Apply brand tokens and `.dark` to `<html>`; styling only an application wrapper does not theme portals mounted outside
it. Multiple independently themed regions require deliberate portal-container handling.

## An app that already uses Tailwind 4

Let the app compile one combined set of utilities. The kit source entry registers its packed component files for
scanning and includes token mappings, animations, and the same dark variant as the precompiled styles. No manual source
paths are needed.

```css
@import "tailwindcss";
@import "@buildkitgg/shadcn-baseui-kit/tailwind.css";

@theme inline {
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-border: var(--border);
}

:root {
  --primary: #6d28d9;
  --primary-foreground: #fff;
}

@layer base {
  body {
    background: var(--background);
    color: var(--foreground);
  }
}
```

Do not import `styles.css`, `styles-no-reset.css`, or either manager's stylesheet in this mode. Those contain compiled
utilities and would duplicate the utilities generated by your app. Tailwind 4 with standard, unprefixed classes is
supported; prefixed or older Tailwind builds should use the precompiled path instead. CSS Modules and ordinary CSS work
with the precompiled path without installing Tailwind.

`theme.css` contains only the default light/dark variables. Importing it alone does not style components. `tailwind.css`
is build input and must be processed by Tailwind; the two compiled stylesheets can be consumed directly by a bundler.

## Light islands

The compiled and source paths share this variant:

```css
@custom-variant dark (&:where(.dark, .dark *):not(:where(.light, .light *)));
```

Inside a dark document, `.light` restores the light default variables and excludes dark utilities. Override brand tokens
on `.light` too when needed. A light island's dialog must use a suitable portal container or carry the light theme on
its portaled content; React context does not propagate CSS inheritance. Nested dark regions inside a light island are
not supported by this selector. App-defined dark variants should use this exact contract.
